# 游戏代码维护说明

## 启动与验证

启动静态服务：`python3 server.py`，然后访问 `http://127.0.0.1:8080/`。

独立服务器开关网站：首次运行 `python3 server-control/server.py --setup` 设置姓名和密码，之后运行 `python3 server-control/server.py`，打开 `http://127.0.0.1:8081/`。登录后页面只有一个“服务器开关”按钮，同时启动或关闭本机8080和局域网192开头地址的游戏服务。控制网站使用独立的8081端口，游戏关闭时仍可访问；手机在同一局域网可用终端打印的8081地址登录。登录信息以加盐密码摘要保存在忽略提交的 `.server-control-data/`，游戏服务器不提供这些文件或控制程序的下载。本地8080页面每秒检查服务器状态，关闭后暂停已加载的游戏并拦截操作；缓存也不能直接打开关闭状态的8080游戏，必须开启服务器后继续。上线部署和原生应用仍保留离线玩法。旧页面更新后需要刷新一次以加载这项检查。

点击开启服务器后，会在新标签页自动进入同一主机的8080游戏主页 `/app.html`；通过局域网控制网站开启时，也使用对应的局域网游戏地址。关闭服务器不会另开游戏页；启动失败时会关闭预留的标签页。若浏览器阻止新窗口，页面提供“进入游戏”链接。

开关按钮下方显示操作进度。开启时进度先到12%停2秒，到50%停6秒，到92%停6秒，确认服务器启动后走到100%并进入游戏；全程显示“启动中…”。关闭时0.5秒连续走完，显示“关闭中…”，并等待服务关闭确认。操作期间不能重复点击开关。

私有在线应用：https://lava-city-game-yyy.proudpearl6.chatgpt.site/app.html 。访问需要所有者账号登录。

手机号演示登录入口在 `phone-login/index.html`，点击获取演示码会直接在页面显示，不发送短信。本地专用服务器 `scripts/serve-phone-app.py` 默认使用演示模式；真实短信需显式添加 `--sms`。Sites 私有网址仍由所有者账号保护。说明见 `phone-login/README.md`。

iPhone / iPad 原生应用工程在 `ios/LavaCity.xcodeproj`，内置游戏文件并保留演示登录。
原生打包与 App Store 上传说明见 `ios/README.md`；签名归档成功不等于已经上传或上架。

应用入口：`http://127.0.0.1:8080/app.html`。在线应用使用 HTTPS 才能在手机上启用
完整安装与缓存；iPhone 用 Safari 的分享菜单添加到主屏幕，Chrome / Edge 使用安装应用。
应用进度仍保存在当前设备，不自动跨设备同步。联机、视频和音乐需要网络。

运行文件复制到 `sites/lava-game/dist/`。超过 25 MB 的音频仅在发布副本中转码，原文件
保留；首次准备需要可用的 `ffmpeg`，也可以通过 `GAME_FFMPEG` 指定其绝对路径。
私有 Sites 项目的身份保存在 `sites/lava-game/.openai/hosting.json`，再次部署时应复用。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `game.js` | 游戏主循环、共享运行状态、入口和 UI 协调 |
| `levels/boot.js` | 关卡注册、地形生成和角色构造工具 |
| `levels/NN.js` | 每关初始地图和场景数据 |
| `levels/NN-*.js` | 特殊关卡玩法及其生命周期钩子 |
| `lib/scenes.js` | 特殊关卡安装、初始化、更新、绘制、离开和点击调度 |
| `lib/levelkit.js` | 场景提示、手绘笔画、指针绑定、准备按钮和笔画几何工具 |
| `lib/progress.js` | 存档读取与字段校验；兼容现有 `yyy_*` 存储键 |
| `lib/util.js` | 数学、HTML 转义、基础存储和共享作用域适配 |
| `lib/draw.js` | 主画面绘制和已有场景交互 |
| `lib/social.js` / `coop.js` | 社交 UI / 联机通信 |
| `audio.js` | 音效与环境声音 |

脚本仍通过 `window` 暴露接口，无需打包。`index.html` 应先加载 `lib/util.js`，
再加载 `lib/progress.js`；关卡脚本和所有公共模块必须在 `game.js` 前加载。
关卡安装函数在主入口运行时才执行，因此此时 `GameLevelKit` 必须已就绪。

## 增加或维护关卡

1. 在 `levels/NN.js` 调用 `GameLevels.register` 注册构建函数。
2. 有独立玩法时，提供 `installXxx(S)`，把生命周期函数挂到 `S` 上，并在
   `lib/scenes.js` 的 `DEFS` 配置钩子。配置中的钩子缺失会在启动时明确报错。
3. 在主入口声明场景状态并加入 `GameUtil.liveScope` 的共享名称，再把关卡脚本加入
   `index.html`。同时检查关卡数量常量、选关配置和测试中的关卡上限。
4. 点击优先级用 `clickOrder` 指定，数字越小越先处理，`0` 是有效优先级。
   `drawAfter` 在该关卡的 `draw` 后调用，适合前景绘制。

现有安装函数通过 `with (S)` 使用共享状态；这些脚本不能直接改成严格模式或
ES module。新增通用逻辑优先通过参数和回调传入依赖，避免继续扩大共享作用域。

## 复用公共工具

- 提示：`GameLevelKit.makeToast(() => scene, 默认秒数)` 创建提示函数；在关卡更新中
  调用 `GameLevelKit.tickToast(scene, dt)`。各关原有默认持续时间应保留。
- 手绘：`createStrokeTool` 负责开始、延长、结束笔画及墨水计量；通过 `makeStroke`
  添加玩法属性，例如盾牌的 `supported` 和水管的 `wet`。
- 指针：`bindDrawPointer` 的 `sceneRef` 仅在对应关卡可绘画时返回场景；用 `isBlocked`
  指定弹窗等阻塞状态，用唯一 `boundKey` 避免重复监听。它只接受发起绘画的指针，
  并处理取消、失焦和指针捕获丢失；返回的清理函数用于卸载监听。
- 存档：新加背包物品时更新主入口的背包默认字段。`GameProgress.load` 只读取这些字段，
  拒绝数组、非法数字和未知物品；写入继续使用现有 `saveJson` / `saveStr`。

## 第二季第18关：自由建造

入口 `season2-lv18.html`。场景是一条平路和开阔的平地，按 B 或点击“背包”，选择砖块、滑梯、水池、啤酒或电视，点击地面或“放置物品”放下。点击已放置物品可分别设置宽度、高度、长度（0.2–60米），也能旋转、移动、复制、删除。单人场景自动保存在本机，最多150件物品。WASD或方向键移动，空格跳跃，拖动画面旋转视角，滚轮调整远近；手机提供屏幕按键。走近滑梯按 E 可以滑下来，走近电视按 E 可开关屏幕。

“联机”创建或加入8位房间码，最多6人共享人物位置和整个建造场景；所有玩家都能编辑物品。后加入的玩家会接收完整场景，消息缺失会重新同步，房主退出后其他玩家继续建造。加入使用房主的场景，退出恢复自己的单人场景；也可主动点击“把房间作品保存到我的单人场景”。需要网络，主、备用线路与第15/16关隔离。

场景数据与校验位于 `lib/build-world.mjs`，物品和人物模型在 `lib/build-visuals.mjs`，共享建造协议在 `lib/build-room.mjs`，联机界面在 `lib/build-online.mjs`。运行 `node --test tests/build-world.test.mjs` 检查物品、存档、分块同步、冲突处理和房主交接；`node scripts/verify-build-online.mjs` 使用三个独立网络客户端验证真实联机，备用线路加参数 `1`。

第18关过山车扩建：背包新增轨道、台阶、轨道停车点、车厢、隧道、下车点和地道开挖。轨道有直轨、上/下坡、360度回环、左/右急弯，以及上坡/下坡同时左/右转，共十种形状。点击“从轨道末端接下一段”连续铺设，或靠近端点自动吸附；离地高度可设为负数。坡高/回环高度与路段长度分别调整，每段轨道还可勾选隧道外壳。

把车厢放到轨道上，同一条相连线路上的下一节车厢会自动联结，车辆间保留连接距离。选中车辆可以乘坐、发车、停车和调整速度；按 E 下车、按 P 发车/停车。停车点停靠5秒，下车点停靠6秒并自动让乘客下车。闭合线路循环运行，未闭合线路在尽头停车。“添加示范线路”提供三节车厢、回环、坡道转弯、站台、地下隧道和台阶组成的可乘坐线路。

“地道开挖”实际切开地表并生成坑壁与底面，高度字段表示开挖深度；相邻或重叠开挖区域会连通。地下视图用于隐藏地表、铺设地下轨道，真实开挖结果仍单独保存和联机同步。台阶可以连接地面与地下。联机通过房间权威校验自动联结车厢，整条示范线路以一个事务同步；车辆启动时间、站台停靠、地下乘客位置和倒立方向均同步给其他玩家。

过山车路径、车队和地道规则在 `lib/coaster.mjs`；模型、真实地形开洞、乘坐运行分别在 `lib/coaster-visuals.mjs`、`lib/coaster-terrain.mjs`、`lib/coaster-runtime.mjs`。`node --test tests/coaster.test.mjs` 验证所有形状、车厢间距、地面开挖、回环倒立、地下行驶和自动下车；`node scripts/verify-coaster-online.mjs`（备用线路加 `1`）用三个独立网络客户端检查联结、启动/停车、地下与倒立乘客、后加入以及房主交接。

### 自由创造存档与游戏圈

- 第18关的“还原”恢复初始场景，并在游戏列表保留完整的还原前备份；联机还原由房间统一同步。
- 每张地图使用独立本机存档，编辑后自动保存、上传；“保存地图并上传、退出”返回 `map-list.html`，可重复进入继续建造。离线时保留存档并显示待上传，可手动重试，网络恢复后也会重试。
- `game-circle.html` 是当前游戏服务器所有玩家共享的动态与聊天，支持标题、游戏/生活分类、文字、内置表情包和图片/动图/视频（每次最多4个附件、单个40MB）。
- 上传地图自动创建标题“快来和我一起玩吧”的动态，后续保存更新同一条动态。其他玩家可以打开独立地图副本，再通过现有联机房间一起玩。
- 使用 `rtk proxy python3 -u server.py` 启动包含游戏圈 API 的服务器。地图、动态和媒体持久存放于被静态服务屏蔽且被 Git 忽略的 `.game-community-data/`，重启服务器不丢失。备份此目录可备份服务器内容。随机发布凭证留在浏览器，清除站点数据后不能自动认领原来的上传身份。
- 静态托管或原生内置离线文件没有该 Python API；未连接游戏服务器时会明确显示待上传，不显示上传成功。共享范围为访问同一游戏服务器的玩家。
- 验证：`rtk proxy node --test tests/build-saves.test.mjs tests/build-world.test.mjs tests/coaster.test.mjs`、`rtk proxy python3 -m unittest discover -s tests -p test_community.py`。
